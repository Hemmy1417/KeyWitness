# KeyWitness brand

The name joins the two things the product does: a key (access to a place) and a witness (someone who saw). The look is
a night archive of built places: quiet, exact, and never decorative where a finding is being read.

## The mark

A doorway arch standing on a threshold, drawn as one line. Inside it sits a keyhole whose slot turns up into a check:
the witness mark. The doorway says property, the keyhole says access under control, the check says something was
examined.

| File | Use |
|---|---|
| `web/public/brand/keywitness-mark.svg` | The mark on its midnight tile. App icon, avatar, anywhere under 48 px |
| `web/public/brand/keywitness-mark-line.svg` | The mark alone in navy and teal, for light paper |
| `web/public/brand/keywitness-logo.svg` | Tile and wordmark in navy, for ivory and white surfaces |
| `web/public/brand/keywitness-logo-reverse.svg` | Tile and wordmark in ivory, for navy surfaces |
| `web/public/favicon.svg`, `web/app/icon.svg` | The mark, served as the favicon |

All five are generated by one script, so they cannot drift apart:

```bash
python scripts/brand.py
```

The script needs `fontTools` (a design-time tool, not an app dependency). It draws the mark on a 64 by 64 grid and
outlines the wordmark from Atkinson Hyperlegible Next at weight 650, so the files render the same on a machine that
does not have the font. The app draws the same mark inline in `web/components/Logo.tsx`.

### Using it

- Keep clear space of half the tile's width on every side.
- Do not use the logo below 20 px tall; use the mark alone there.
- Do not recolour, outline, stretch or rotate it, and do not set the wordmark in another typeface.
- On a photograph or a busy surface, use the tile version: the tile is the mark's own background.
- The teal of the keyhole is the brand accent. It is not the finding colour for "supported", which is a darker teal
  chosen for text contrast; do not use the logo to signal a finding.

### Finding colours

Reserved for findings. Each one always travels with an icon and a word, so nothing depends on colour alone.

| Finding | Token | Value | Icon |
|---|---|---|---|
| Supported | `--color-supported` | `#0f6b5f` | Check |
| Not established | `--color-adverse` | `#a3261c` | Cross |
| Conflicting | `--color-uncertain` | `#8a5300` | Split |
| Insufficient | `--color-uncertain` | `#8a5300` | Gap |
| Not assessed | `--color-neutral` | `#4c5664` | Dash |

Conflicting and insufficient share amber on purpose: both mean "no conclusion", and the word and icon tell them apart.
Red is used for a finding that the evidence shows a criterion is not met, and for errors. It is never used for "no
conclusion", so an uncertain result cannot be mistaken for an adverse one.

Every text colour is checked at 4.5:1 or better against the surface it sits on.

## Type

| Face | Use | Licence |
|---|---|---|
| Atkinson Hyperlegible Next | All text | SIL Open Font License 1.1 (`web/app/fonts/OFL-AtkinsonHyperlegibleNext.txt`) |
| Atkinson Hyperlegible Mono | Digests, addresses, identifiers, amounts in a review | SIL Open Font License 1.1 (`web/app/fonts/OFL-AtkinsonHyperlegibleMono.txt`) |

Both are self-hosted from `web/app/fonts/`, so a build makes no request to a font service. They were chosen because
evidence has to be read: letterforms that are hard to confuse (I, l, 1; O, 0) matter when the text is a digest or an
exhibit number.

The scale stops at 44 px. Labels are sentence case; nothing is set in capitals for emphasis.

| Class | Size | Use |
|---|---|---|
| `t-display` | 30 to 44 px | One statement per page |
| `t-h1`, `t-h2`, `t-h3` | 26 to 34, 24, 20 px | Headings |
| `t-body` | 17 px | Running text |
| `t-small`, `t-micro` | 15, 13 px | Supporting text, captions |
| `t-label` | 14 px bold | Field and section labels |
| `t-mono` | 14 px | Machine values |

## Shape and surface

- Square corners on cards, 1 px hairlines, no shadows. Depth comes from the navy plates against the ivory page.
- Controls are outlined. One filled ink button marks the primary act of a view; a second filled button on the same
  view is a mistake.
- Evidence is shown as an exhibit tag with a keyhole punch at its left edge.
- Focus is a 3 px amber outline with a 2 px offset on every interactive element.
- Motion is limited to state changes and is removed entirely under `prefers-reduced-motion`.

## Voice

- Say what was recorded, by whom, and what it does not prove. "The validators found the criterion supported" is a
  record; "the repair happened" is a claim the product never makes.
- Name people by role (claimant, respondent, inspector), exhibits by number, and dates in words. Addresses, digests and
  identifiers appear only in views labelled for verification.
- A refusal gives the reason the contract gave, in a sentence.
- No superlatives and no promises about legal standing.

## Source of the look

The layout language was adapted from a reference on styles.refero.design (Aspelin Reitan's architectural archive):
full-bleed dark plates alternating with warm paper, square hairline cards and outlined controls. The palette, the type,
the exhibit tags and the mark are KeyWitness's own.
